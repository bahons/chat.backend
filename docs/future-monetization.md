# Future-only: будущая монетизация (не строить сейчас)

**Решение владельца продукта:** на старте ВСЁ БЕСПЛАТНО — регистрация, верификация, чаты, медиа, звонки, мобильное и веб-приложение, бизнес-инструменты. Никаких paywall, checkout, оплаты, платных ограничений.

В ТЗ сохранить возможные планы `Free`, `Business`, `Pro`, `Enterprise` для будущего коммерческого решения. Не добавлять платежные таблицы, `isPaid` guards, price checks и vendor payment SDK в MVP. В коде оставить чистые границы модулей (e.g. `BusinessEntitlements` interface **только если это реально нужно для modular design**), но сейчас все возможности доступны всем в рамках продуктовых/безопасностных правил.

Перед монетизацией отдельно согласовать тарифы, налог/юр модели, billing provider, meter usage, quota policy, migration, grace periods, refund, invoicing, privacy, поддержку действующих клиентов. Не путать технические anti-spam ограничения с тарифными лимитами.
