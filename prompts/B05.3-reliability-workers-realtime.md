# B05.3 — Realtime, Workers, Delivery & Media Reliability

## Role and prerequisite
You are Codex in **`chat-backend`**. Read `AGENTS.md`, `docs/implementation-status.md`, `docs/hardening/B05.2-results.md` if present, `docs/contracts/events-v1.md`, `docs/security.md`, `docs/architecture.md`, current Outbox/Push/SMTP/Media implementations and tests. Check the actual repository; do not assume B05.1 or B05.2 passed if no evidence exists. Flag blockers first.

## Scope
Address **RT-01, RT-02, MEDIA-01, MEDIA-02, OPS-02, OPS-03** and related worker resilience. Prioritize correctness, at-least-once side-effect semantics and ACL enforcement. No B06/WebRTC, unrelated UI, billing or new product features.

## 1. RT-01 — business access revocation
- Unify authorization for events and membership/active-session checks. `BusinessAccessRevoked` must not disclose business identifiers or reasons to invalid, inactive or revoked users. Clearly define whether verified clients should receive a business suspension event; never leak privileged admin details.
- Ensure connections are actually disconnected/denied on revoked JWT family, removed membership and business suspension, on the documented bounded schedule. Do not rely solely on sending a notification. Review `LeaveConversation` / `SetTyping` permission checks and event payload shapes.
- Add integration tests for membership removal, suspension, reauthentication, stale session and unauthorized group join/leave/typing.

## 2. RT-02 — scaling and outbox
- Existing local connection registry + DB `SKIP LOCKED` loses events across 2 API replicas. Implement a **documented deliberate choice**:
  **Option A (initial release):** enforce exactly one active API replica and one eligible event-dispatch worker in deployment configuration; implement startup/deploy guardrails against accidental multi-replica rollout, alerting for backlog, and document this non-scaling limit.
  **Option B (if architecture already supports it):** implement shared SignalR backplane / managed service or reliable fan-out with explicit routing, retries and multi-replica tests.
- Do **not** claim multi-instance support by adding Redis alone; ensure the outbox consumer cannot acknowledge events that missed all target connections.
- Bound connected clients/subscriptions, memory, work queues, event lag, retries and fan-out cost. Never drop an event as delivered solely because the local worker had no socket; use reconnect + REST catch-up and clear semantics.

## 3. OPS-02 — no outbound I/O inside long DB locks
- Refactor Outbox/Push workers to claim short leases / records atomically, **commit**, perform remote SignalR/Expo I/O **outside** DB transaction, then mark result in a short transaction. Handle lease expiry, worker crash, retries, concurrent workers, cancellation, idempotency and duplicate send windows.
- Explicitly document at-least-once delivery, message/client deduplication keys and limits; do not promise exactly-once push notifications when provider APIs cannot guarantee them. Test slow/unavailable Expo gateway and concurrent ACL changes.

## 4. OPS-03 — reliable SMTP
- Replace ephemeral in-process-only registration/reset delivery path with durable mail intent / outbox committed atomically with the relevant account state. Implement bounded retries with backoff, dead-letter or operator-visible failure, safe redaction and idempotency.
- Mail tokens and URLs must not leak into application logs, status endpoints or queue metadata in plaintext unless encrypted with an explicitly documented key management approach. Design expiry/re-request flow for stale verification/reset links.
- Test SMTP outage, crash/restart, queue pressure and duplicate delivery behavior. Return honest API state: avoid claiming actual delivery when only queued.

## 5. MEDIA-01 — signed link residual access
- Preserve ACL checks before issuing links. Document existing issued S3 GET URL (up to 1 minute) / PUT URL (up to 5 minutes) residual access and window between check and issue; set and test minimum practical TTL, avoid caching sensitive URLs and prevent old temp PUT from becoming a READY attachment after revocation.
- If immediate revocation is a requirement, provide a **separate proposal** for proxy/credential mediation, with cost and performance impact. Do not falsely claim immediate revocation for pre-signed URLs.

## 6. MEDIA-02 — scanning, retries, object lifecycle
- Distinguish scanner unavailable / network error / protocol error from positive malware detection; define retries, quarantine and fail-closed access. Preserve B05.1 verification-document protections if already added.
- Cover object-store copy succeeded + DB failure, duplicate complete, abandoned `PENDING`, quarantined objects, ready-but-unattached objects and background cleanup. Cleanup must never delete a still-referenced ready file. Use lifecycle policies only alongside metadata safety checks and retention policy.
- Integrate temporary object cleanup with measured limits/metrics. Test using PostgreSQL, MinIO, ClamAV/test doubles as practical; make external dependencies explicit.

## Constraints
- Keep all B2C access restrictions and company verification gates. No secrets in logs/events; no destructive silent changes to existing data.
- Maintain SignalR event name/payload compatibility where possible. For any required contract change update `docs/contracts/events-v1.md`, `docs/contracts/api-v1.md`, OpenAPI and cross-repo handoff, and mark breaking changes for approval.
- Do not simulate success with mocked external gateways only; use integration scenarios and clearly identify what remains untested on real devices or production infrastructure.
- Single-replica is an acceptable **documented and enforced MVP constraint**; multi-replica without test evidence is not.
